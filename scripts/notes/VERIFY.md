# 紹介文の事実の照合

書かれた紹介文の各文が、出典テキストで裏付けられるかを確かめる。照合を通った記事は人の確認なしでサイトに公開されるので、**迷ったら通さない**。照合する人は、その記事を書いた人とは別の人（別のサブエージェント）にする。

## 入力と出力

- 入力: `data/notes/verify/input.json`（`auto_publish.py export` が書き出す）。記事ごとに `batch_id`・`wiki_title`・`tracks`（DB 上の曲）・`sentences`（紹介文を文に分けたもの）・`source_text`（Wikipedia から整形した出典）
- 出力: `data/notes/verify/results.json`（入力が複数のファイルに分かれているときは、指示されたファイル名に）

```json
[
  {
    "batch_id": "（入力のまま）",
    "wiki_title": "（入力のまま）",
    "same_work": true,
    "same_work_reason": "",
    "sentences": [
      {"text": "（入力の sentences の1文をそのまま）", "verdict": "supported", "evidence": "出典の該当箇所", "reason": ""}
    ]
  }
]
```

- `sentences` は入力と同じ数・同じ順番・同じ文字列で返す（1文字でも違うと照合結果が使われない）
- `verdict` は次のどれか
  - `supported`: 文の中の事実（人名・作品名・数字・順位・年・タイアップ・「初」「最後」などの限定）がすべて出典に書かれている。言い換えはよい
  - `unsupported`: 出典にない事実が1つでも入っている、または出典と食い違う
  - `unclear`: 出典の読み方によって正しくも誤りにもなる（主語が曲か歌手か、どの盤の話か、いつの話か、など）
- `supported` 以外のときは `reason` に何が足りないかを短く書く
- `evidence` は出典の該当箇所をそのまま短く引用する

## 確かめること

1. **同じ作品か**（`same_work`）: 出典の記事が `tracks` の曲（曲名・アーティスト・発売日）と同じ作品か。同名の別の曲、カバー元の原曲、別アーティストの記事なら `false` にして理由を書く。シングルの曲が収録アルバムの記事で書かれているときは、文がその曲についての記述だけなら `true`
2. **文ごとの事実**: 出典にあることだけでできているか。とくに次は厳しく見る
   - 数字（順位・枚数・回数・年・何枚目）と、計算して作った数字（「◯年ぶり」を出典にない年から出していないか）
   - タイアップが表題曲のものか、リミックス・別バージョン・カップリング曲のものか。発売時のものか、後年のものか
   - 賞の受賞者（曲・歌手・作詞家のだれが受けたか）
   - 「初」「唯一」「最後」「自己最高」などの限定
   - 伝聞（「〜とされる」）を断定にしていないか
3. 文体や書き方の良し悪しは見ない（それは機械チェックとレビューの役目）

自分の知識で「正しい」と思っても、出典になければ `unsupported`。出典が誤っていそうでも、出典どおりなら `supported`。
