# 紹介文の執筆ルール

ReleaseTuneは「今日はあの曲のリリース日」をテーマにしたサイト。紹介文は、その曲を知っている人には当時を思い出すきっかけに、知らない人には聴いてみたくなるきっかけになるものを目指す。

## 入力と出力

- 入力: `data/notes/pending.json`（`export_pending.py`が書き出す）。記事ごとに次の項目がある
  - `wiki_title`: 出典の記事名
  - `tracks`: DB上の曲（曲名・アーティスト・発売日）。同じ記事に複数の曲（シングル盤とリマスター盤など）が対応することがある
  - `source_text`: Wikipediaから整形した出典テキスト
  - 書き直し依頼（`status: "rewrite"`）の場合: `reviewer_comment`（レビューでの指摘）と`previous`（前回の下書き）
- 出力: `data/notes/drafts.json`

```json
[
  {
    "wiki_title": "（pending.json の wiki_title をそのまま）",
    "note_short": "短文",
    "note_long": "長文（書けなければ空文字）",
    "facts": [
      {"claim": "書いた内容", "source": "出典テキストの該当箇所（そのまま短く引用）"}
    ],
    "review_note": "（任意）レビューで見てほしい点。書いた記事は人が確認する"
  },
  {"wiki_title": "…", "skip": true, "skip_reason": "見送る理由"}
]
```

## 短文（`note_short`）

- 表示場所: 日付ページのカード、注目曲。曲名・アーティスト名・発売日は画面に出ているので書かない
- 60字以内、1〜2文
- 文末は体言止めを基本にして短く締める（「花王「AUBE」のCMソング。」「オリコン最高6位。」「累計19万枚を記録。」）。動詞で終わる文は「〜となりました」のような「ます」形でもよい
- いちばん伝えたい事実を1〜2個。優先順位は次のとおり
  1. タイアップ（ドラマ・映画・アニメ・CMなど）
  2. チャート最高位・売上・認定
  3. 受賞、紅白歌合戦への出場など
  4. 作詞・作曲者や制作の特徴
  5. 何枚目のシングル／アルバムか
- 例（形の参考。事実は出典から）:「ドラマ『◯◯』の主題歌。オリコン週間1位を獲得。」

## 長文（`note_long`）

- 表示場所: 楽曲詳細ページ（出典としてWikipediaの記事へのリンクが下に付く）
- 150〜400字
- 構成の目安: 位置づけ（何枚目の作品か、どんな曲か）→ 制作の経緯・背景 → タイアップ → 反響（チャート・売上・受賞）→ その後（カバー・再録など）。出典にない要素は飛ばす
- 出典の情報が少なく150字に届かないときは、長文は空にして短文だけにする。一般論や言い換えの繰り返しで水増ししない
- 短文と同じ事実を含めてよいが、言い回しは変える

## 事実の扱い

- 出典テキスト（と、下の「Wikipedia 以外の情報源」で認めたページ）に書かれていることだけを書く。自分の知識で補わない（正しいと思っても、出典になければ書かない）
- 数字（順位・枚数・年・回数）は出典の表記どおりに書く。計算して新しい数字を作らない（「発売から◯年」「◯年前」は書かない）
- 出典が伝聞（「〜という」「〜とされる」）なら、断定せず伝聞のまま書く
- 出典の記事がDBの曲と別物（別アーティストの同名曲、カバー元の原曲の記事など）だと判断したら`skip`にする
- DBの曲がリマスター盤やEPでも、発売日が合っている記事なら元の曲について書いてよい
- DBの曲がシングルなのに、出典がそれを収録したアルバムの記事のとき（曲の記事がアルバムの記事へ転送されている場合）は、記事の中のその曲についての記述だけで書く。アルバム全体の紹介にしない。曲についての記述がなければ`skip`にする
- 各記述の根拠を`facts`に記録する。レビューでの確認に使う
- タイアップが表題曲そのものではなく、リミックス・別バージョン・カップリング曲に付いている場合は、そのことを書く（表題曲のタイアップとして書かない）
- 発売から時間がたってからのタイアップ（再発時や数十年後のCM起用など）は、当時のタイアップと誤解されないよう時期を明記して長文に書く。短文には書かない
- Infoboxの「認定」欄には歌手個人への賞も並ぶ。賞を書くときは「この曲で◯◯が受賞」のように受賞者をはっきりさせ、曲そのものへの賞と断定しない（本文で曲への賞と書かれている場合は除く）
- 出典の中で数字や名称が食い違うとき（基本情報と本文、関連記事どうしなど）は本文の記述を優先し、判断できなければその事実は書かない
- 出典の範囲を広げない。「アルバムとしては初」を「作品として初」に、「移籍第1弾（アルバム）」を「移籍して最初の作品」に、「タイアップの効果」を「映画のタイアップの効果」にしない。「初」「唯一」「最大」「最後」は、出典が限っている範囲（アルバム・シングル・ソロ名義など）ごと書く
- 別々に書かれている事実を「〜し、〜」「〜ため」「〜により」でつながない。出典が因果を書いていなければ、文を分けて並べる
- 「この」「その」「同じ」で前の文を受けるのは、出典が同じものだと書いている場合だけ（「この英語版」が前の文のリミックス版と同じものか分からない、など）
- 題名・番組名・商品名は出典の表記どおりに全部書く（「不良1/2」を「不良」にしない）
- 出典の書き方があいまいで、どちらにも読める記述は書かない（「11ラジオ局のパワープレイでチャートを獲得」を「11局でパワープレイに選ばれ」と読み切らない）
- DB の曲（配信シングルなど）と出典の記事（収録アルバムなど）の盤が違うとき、チャートや売上がどの盤の記録か出典で分からなければ書かない
- 賞を書いた記事は、照合を通っても必ず人の確認に回る（受賞者の取り違えが多いため）。曲そのものの受賞と出典ではっきり言えるときに書く。歌手個人や作詞家の賞は、書くなら受賞者を主語にする

## Wikipedia 以外の情報源

出典テキスト（Wikipedia）にない事実は、次のページで確かめられれば書いてよい。使った記事は必ず人がレビューする（自動公開されない）ので、出典テキストだけで十分に書ける記事では無理に使わない。

- 使ってよい
  - アーティスト・レーベル・タイアップ先（ドラマ・映画・アニメ・CM の企業）の**公式サイト**
  - **Wikidata**（`wikidata.org`）・**MusicBrainz**（`musicbrainz.org`）
  - **英語版 Wikipedia**（`en.wikipedia.org`）
  - **日本レコード協会**のゴールドディスク認定（`riaj.or.jp`）
  - **Billboard JAPAN**（`billboard-japan.com`）・**オリコン**（`oricon.co.jp`）のチャートのページ
- 使わない: ニュース記事の本文の書き写し、歌詞サイト、SNS・ブログ・個人サイト・ファンの wiki、通販サイトの商品説明、ほかの AI の回答
- 書き方
  - その事実の `facts` に、`source_url`（ページの URL）と、`source`（そのページの該当箇所をそのまま短く引用）を書く。`source_url` のない facts は出典テキストからの引用として扱う
  - 出典テキストと食い違うときは出典テキストを優先し、食い違いは `review_note` に書く
  - ページの文をなぞらない（出典テキストと同じく、自分の言葉で書く）
  - 発売日・曲名・アーティスト名がサイトの DB（`tracks`）と違うページは、別の盤や別の曲の可能性があるので使わない

## 表現

- 文末: 名詞で終わる文は「です」を付けずに体言止めにする（「作曲は菊池一仁。」「自身初のマキシシングル。」「4か月ぶり。」）。動詞で終わる文は「〜ました」「〜ています」の「ます」形にする。「である」「だ」「した」などの常体は使わない
- 出典の文をなぞらない。語順や構成を組み替えて、自分の言葉で書く（出典と20字を超えて一致すると機械チェックで指摘される）
- 評価語（名曲・代表曲・大ヒット・伝説・不朽など）は、出典に書かれている場合だけ使う
- 使わない: 「Wikipediaによると」、「◯年前」、推測（「〜だろう」）、感嘆符、絵文字
- 作品名（ドラマ・映画・番組・アルバム）は『』、曲名とCMの商品名は「」
- 感嘆符を使わないのは地の文の話。番組名などの固有名詞に含まれる「!」はそのまま残す
- 人名は出典の表記に合わせ、初出はフルネームで書く（「浜崎」ではなく「浜崎あゆみ」）。敬称は付けない

## 見送り（`skip`）

- 出典に発売日と作詞・作曲者くらいしか情報がなくても、短文は書ける（例:「◯◯が作詞・作曲を手がけた3枚目のシングルです。」）
- 短文すら書けない場合（出典が別の曲の記事、情報がほぼ空など）だけ`skip`にし、理由を`skip_reason`に書く
